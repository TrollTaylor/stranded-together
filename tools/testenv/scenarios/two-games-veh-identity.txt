# Shared real vehicles, identity (design M2.10 #1; docs/real-partner-body.md section 23), hidden:
#   pwsh -File tools\testenv\Start-TestRun.ps1 -Scenario two-games-veh-identity -SeedSaves complete-100 -GuestSeed profile-only
# host_save=1 on both games, vehicle_sync unset: the real shared vehicles (vehicle_sync=5) are on when their byte checks pass.
# The host Continues; the guest receives the host's save (M1) and loads it. Then the guest asks for the host's vehicles
# (SNAP_REQ, channel 3), the host sends its table in chunks (SNAP), and the guest binds every host vehicle to its own unit
# (the same GUID, else the same id within 5 m), re-places or removes a wrong unit under a host id, and removes its own
# units the host does not have. Both games dump their pools (compare the T1 dumps: every host unit bound, same id / GUID,
# under 0.5 m). Phase B: the guest summons a trike through its game's own request path; its gate drops the request and
# forwards it (REQ), the host's game spawns it and announces it (ADD), the guest mirrors it (the log names the path:
# exact-id, fallback spawn or re-place). The T2 dumps show one new trike per world (the same id after the exact-id path).
# Stage 2: the host's park frames (STD1 PARK) place the guest's units where the host's stand ("[vdrive] ... parked:
# placement error" lines; vehicle_drive 1 at the end: frames received, corrections per band).
# Check: 01-host-world / 01-guest-world (the same vehicles in the same places), 02-*-summon (the trike on both screens).
role host
graphics low
timeout 360
ini host_save=1
ini partner_body=real
waitready 90
@guest waitready 120
waitlog 120 \[overlay\] input attached
@guest waitlog 120 \[overlay\] input attached
waitlog 10 \[coop\] host-held save session ON \(host
@guest waitlog 10 \[coop\] host-held save session ON \(guest
waitlog 60 \[vshare\] shared real vehicles ON \(host
@guest waitlog 60 \[vshare\] shared real vehicles ON \(guest
waitlog 10 \[vdrive\] remote driving ON \(host
@guest waitlog 10 \[vdrive\] remote driving ON \(guest
waitlog 10 \[vehicle\] vehicle sync real
@guest waitlog 10 \[vehicle\] vehicle sync real
# the title menus (~20 s after the first frame); the host Continues (CONTINUE is selected on its title)
wait 22000
waitlog 30 \[link\] CONNECTED
pad A 150
waitlog 30 \[coop\] host: title Continue
@guest waitlog 120 \[coop\] guest: wrote the host's save #1 as manualsave5
until 240 5000 \[sync\] local player entity 0+ -> 0*[1-9A-F] => pad A 120
waitplayer 60
@guest waitlog 180 \[coop\] guest: in the world after
@guest waitplayer 60
# the vehicles: the guest's binding against the host's table
waitlog 60 \[vshare\] host: world ready
@guest waitlog 60 \[vshare\] guest: world ready
waitlog 60 \[vshare\] host: snapshot #[0-9]+ \(asked\)
@guest waitlog 60 \[vshare\] guest: the host's snapshot #[0-9]+ is complete
@guest waitlog 30 \[vshare\] guest: binding:
# the grace time (placement vehicles stream in), then the dumps
wait 20000
action vehicle_dump 1
@guest action vehicle_dump 1
@guest action vehicle_share 4
action vehicle_share 7
@guest action vehicle_share 7
action vehicle_share 0
@guest action vehicle_share 0
snapshot
@guest snapshot
screenshot 01-host-world
@guest screenshot 01-guest-world
# phase B: the guest summons a trike through its game's own request path
@guest action vehicle_summon 3 8
?@guest waitlog 20 \[vshare\] guest: our game asked for a trike
?waitlog 20 \[vshare\] host: the guest's game asks for a trike
?waitlog 20 \[vshare\] host: ADD trike
?@guest waitlog 30 \[vshare\] guest: mirror 0x[0-9A-F]+ \(trike\)
wait 10000
action vehicle_dump 2
@guest action vehicle_dump 2
action vehicle_share 0
@guest action vehicle_share 0
screenshot 02-host-summon
@guest screenshot 02-guest-summon
@both action vehicle_drive 0
@both action vehicle_drive 1
@both action log_status
nolog \[vshare\].*FAULT
@guest nolog \[vshare\].*FAULT
nolog \[vdrive\].*FAULT
@guest nolog \[vdrive\].*FAULT
@guest quit
wait 3000
quit
