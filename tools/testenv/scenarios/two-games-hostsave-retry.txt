#   pwsh -File tools\testenv\Start-TestRun.ps1 -Scenario two-games-hostsave-retry -SeedSaves complete-100 -GuestSeed profile-only
# Both start from the host's Continue. Then the host makes the checkpoint retry the Game Over screen's Retry makes
# (`action coop_session 7`: 0x14362D750 with index -2, reason 5, only while the game says a checkpoint exists; a test
# stand-in for dying and pressing Retry). There is no file for the in-memory checkpoint: the host's mod offers its
# newest autosave marked approx (reason Retry) and the guest loads it in the world. The distance between the host's
# and the guest's spawn after the retry measures the -2 versus newest-autosave question (compare the snapshots).
# Check enlarged: 03-host-after-retry / 03-guest-after-retry (the guest at the newest autosave; the host where it was, see
# below: no checkpoint exists in a freshly loaded world, so the game ignores the request).

# the retry: the newest autosave stands in for the in-memory checkpoint (approx). A freshly loaded world has no
# checkpoint (every load request clears it; runs 20261119-072858 / -073105 polled 0x14362B4A0 for 3 minutes of walking: absent),
# so the Game Over screen could not offer Retry here: `7 2` makes the same request anyway. The game itself ignores a
# -2 / reason 5 request without a checkpoint (0x14362D750 checks 0x14362B4A0), so the HOST DOES NOT MOVE: this proves
# the detection, the approx offer and the guest's in-world load, not where a real retry puts the host.

action coop_session 7 2
